# dynamic-bot-qqbot

QQ 官方机器人插件，用于让 dynamic-bot 通过 QQ 开放平台的官方机器人，在 QQ 群和单聊中收发消息。

主项目：[dynamic-bot](https://github.com/Colter23/dynamic-bot)

## 功能

- 发送 QQ 群消息和单聊消息，也支持撤回。
- 发送图片、视频和语音；本地文件由插件直接上传给 QQ，不需要公网地址。
- 接收 QQ 群消息和单聊消息，用于命令、自动链接解析和其他插件（例如翻译插件）。
- 回复消息时以引用形式带上原消息。
- 自动积累可发送目标：收到过消息的群和好友会出现在后台“可选目标”里，无需手填 OpenID。
- 自动补全群名称，平台账号显示机器人真实名称与头像。
- 解析消息中的卡片链接（例如 B 站视频分享），配合主项目的链接解析开关使用。
- 群聊支持 @全体成员：命中订阅的 @全体事件时使用官方 `<qqbot-at-everyone />`，不满足条件时自动降级为纯文本。
- 连接断开后自动重连，并保留会话补发断开期间的事件，不丢消息。

## 安装

构建插件：

```powershell
.\gradlew.bat fatJar --offline
```

把生成的 `*-all.jar` 放入主程序的 `plugins/` 目录，然后启动或重启 dynamic-bot，在后台启用插件。

使用前需要先在 QQ 开放平台创建机器人，拿到 `AppID` 和 `AppSecret`，并把机器人拉进目标群（单聊则需用户添加机器人）。

## 配置项

插件默认未启用。启用前至少需要：

```yaml
enabled: true
appId: "你的 AppID"
appSecret: "你的 AppSecret"
reconnect: true
autoPublishIncoming: true
```

- `appId` / `appSecret`：QQ 开放平台分配的机器人凭据。
- `reconnect`：连接断开后是否自动重连，建议保持开启。
- `autoPublishIncoming`：收到消息后是否交给主项目处理，命令、链接解析和其他插件都依赖它，建议保持开启。

事件订阅不需要配置，插件已固定订阅自己需要的全部事件类别。

## 平台 ID

本插件的平台 ID 是 `qq-official`，与 OneBot 插件的 `qq` 是两个独立平台。

QQ 官方的目标标识是 OpenID（一串十六进制字符），OneBot 是 QQ 号，两者不能通用。分开后后台的平台下拉、目标列表、路由策略和链接解析目标配置各自独立，避免两个插件互相串线。

## 使用建议

- 后台的“可选目标”来自插件真实收到过的消息。新部署时列表是空的，需要先在群里 @ 一次机器人（或让好友给机器人发条消息），目标才会出现。
- 图片、视频交给插件直接发送即可，不需要为它配置公网地址。
- 群名补全和机器人资料都受官方接口频控，偶发失败会自动退避重试，不影响消息收发。

## 注意事项

- **群聊 @全体成员有前提**：机器人必须是该群管理员，且每个群每天仅 1 次。不满足条件时会自动降级为纯文本 `@全体成员`，消息本身照常发送；只有文本消息能 @ 全体，图片等富媒体消息会额外补一条文本消息。
- **主动消息有频控**：未认证群聊每分钟 30 条、每群每天 1000 条，短时间内大量推送可能触发限制。
- **被动回复有时间窗口**：群聊 5 分钟、单聊 60 分钟，超时回复会失败（翻译这类即时回复不受影响）。
- **撤回窗口为 2 分钟**，超时无法撤回。
- 目标（群 / 好友）**不显示头像**：官方没有提供目标头像，只能显示名称，名称取不到时显示 OpenID。
- 合并转发消息官方不支持，主项目会自动降级为文本。

## 排查连接问题

需要排查时，把主程序日志级别调到 `DEBUG`（环境变量 `LOG_LEVEL=DEBUG`），可以看到连接过程、心跳与事件解析细节，无需修改插件配置。

正常运行时插件不会刷日志：一次自动重连只输出一条「会话已恢复」，失败才会告警。
